# GPT providers / settings / cost telemetry gotchas

Reference: `docs/architecture.md` § GptMaster.

- `chat_gpt.providers` holds API credentials; `chat_gpt.settings` holds named configs (`agent`, `agent_vision`, `image_prompt`, `knowledge`, `lyrics`, `embedder`) referencing providers
- `GptMaster.new(messages, setting:, chat_id:, purpose:, system_prompt:, report_errors:, record_usage:)` resolves provider + model from settings; the `setting:` kwarg picks one of the named blocks under `chat_gpt.settings`. **Every consumer must pass `setting:` explicitly.** The kwarg default is still `'main'` but `main` is no longer defined — any forgotten caller fails loudly with `Unknown chat_gpt setting: main` rather than silently picking some other model. `report_errors:` defaults true. Set it false only when the LLM call is either the synthetic `runtime_error` explanation turn (to prevent recursive provider-error events) or optional best-effort enrichment with a deterministic local fallback. `record_usage:` also defaults true; only the standalone model canary disables DB usage writes. Active settings: `agent` (Agent::Runner tool loop and general text work; `deepseek-flash`/V4.1 Flash, thinking disabled, max 4096), `agent_vision` (image-attached Agent::Runner turns; the same multimodal model, thinking disabled, max 4096), `image_prompt` (ImageGenTaskHandler T2I + edit enrichment; `deepseek-flash`, thinking disabled, max 768 tokens), `knowledge` (KnowledgeBase extraction/compaction on `deepseek-flash`), `knowledge_review` (cheap mechanical judge on `deepseek-flash`), `lyrics` (Suno long-form creative text on Claude Sonnet 5 with thinking explicitly disabled), and `embedder` (OpenAI `text-embedding-3-small`). Moving agent and knowledge from the still-available, text-only V4-Pro-0813 to V4.1 Flash is intentional. `chat_id` + `purpose` feed the `api_usage` table (telemetry is fire-and-forget — errors logged, never propagated).
- **`max_tokens` on OpenAI-compatible providers** — sent only when the setting defines it (was Anthropic-only until 2026-09; DeepSeek ran on its 65,536 default). On DeepSeek V4 thinking, **reasoning counts toward `max_tokens`** and a truncated turn comes back `stop=length` with empty content — size from prod output (`jq` over gpt.log `usage.output` per purpose), not from the visible reply length: knowledge extraction is ~90% reasoning (p99 10k). xAI accepts `max_tokens` but excludes reasoning. Adding `max_tokens` to a setting that lacked it changes behavior for every call on it.
- **A 200 can be unusable** — `GptMaster#usable_body` rejects unparseable / non-Hash bodies and ones missing `content` (Anthropic) or `choices[0].message` (OpenAI) before any `[]`/`dig`; new response-reading code must go through the parsed Hash it returns, never `response.dig` on the HTTParty object (a String body raises NoMethodError — prod 2026-09-02). Unusable 200s and terminal non-200s with a `chat_id` also go through `Agent::ErrorReporter` so the failure can re-enter the agent loop; parentless fingerprint coalescing prevents repeated provider faults from flooding it.
- **Prompt caching:** the `agent_prompt` template in `settings.common.yml` contains a `{CACHE_BREAK}` marker. Everything before it is sent as the Anthropic `system` param with `cache_control: { type: 'ephemeral' }`; everything after is the dynamic user message. Agent tools also get `cache_control` on the last tool in the array. Second+ calls within 5 min hit the cache (`cache_read_tokens > 0`, much cheaper input). OpenAI-compatible providers auto-cache; the split is harmless for them. `GptMaster.ask` does **not** cache — its prompts vary per call.
- **Agent answer-quality policy is prompt-pinned.** Correctness/action truth comes before humor; uncertainty and corrections are explicit, and invented explanations for failures/latency are forbidden. Ordinary replies default to 1–3 sentences/~500 characters, one contextual joke, no unsolicited participant census, and no stock «печь»/«выползет сам»/«Дзен постигнут»/✌️ ending. `get_random_phrase` is only for an explicit phrase/insult/persona request. Search is required for current, niche factual, medical/high-stakes, or explicit lookup requests; otherwise answer directly. Bound a fact lookup to one initial query plus one reformulation, then disclose uncertainty. Keep the translation-only and trusted task-state paragraphs intact when editing persona wording. `test/model_settings_test.rb` pins these invariants.
- `chat_gpt.pricing` (in `settings.common.yml`) maps exact model id → `input`/`output`/`cache_read`/`cache_write` in USD per 1M tokens. `ApiUsage.compute_cost(model, usage)` returns cents as `BigDecimal`. Unknown models → row with `cost_cents = 0` + warn log
- `бот затраты` / `бот расходы` / `бот cost` (admin-only) prints a Markdown digest of API costs broken down by purpose for today / 7d / 30d, plus top-5 spenders per window in the current chat, and global totals
- **Telemetry convention** — every `GptMaster` call persists a row to `api_usage` with the `chat_id`, `user_uid`, and `purpose` you pass. Always pass all three where possible so `бот затраты` can attribute costs and show top spenders. If you add a new call site, pick a short snake_case `purpose` label and use it consistently. Background tasks that don't have a triggering user (knowledge extraction, compaction) leave `user_uid` nil — the top-spenders section filters those out.
- Every successful or unusable-200 `gpt.log` record includes top-level `took_ms`; keep that per-call latency when changing the dump format. `bin/agent-model-canary` is the safe, opt-in real-token comparison: it advertises inert read-only tools but never runs Runner/tool handlers. It uses the configured CloseRouter agent when present, or `CANARY_CLOSEROUTER_MODEL`, and reports a clean skip when a model/key is absent.
